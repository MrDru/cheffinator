Recipe Manager 
Product Specification Document 
Version 1.0 – December 2025 
Executive Summary 
Recipe Manager is a web application designed for home cooks who want a simple, elegant way to create, store, and manage their personal recipe collection. The app prioritizes ease of recipe entry with a clean, distraction-free interface that makes writing recipes feel natural and enjoyable. 
The core philosophy: writing a recipe should be as simple as jotting it down on paper, but with the organizational power of a digital tool. 
Project Goal 
The primary goal is to deploy this web application to a server and make it publicly accessible via a custom domain. Anyone with the link will be able to use the app to manage their recipes. 
Deployment Strategy 
• Custom Domain: A dedicated domain will be purchased for easy access and professional branding 
• Hosting Preference: Self-hosted on a local machine that remains always-online, with cloud hosting (e.g., Vercel, Netlify, DigitalOcean) as a fallback option • Public Access: The app will be available to anyone via the domain link—no login required for basic usage 
• Data Persistence: Backend database will be required to store recipes across sessions and users 
Product Vision 
Target Users 
Home cooks who want to digitize family recipes, experiment with cooking, or simply keep their recipe collection organized. Users range from occasional cooks to passionate home chefs who create and modify recipes frequently. 
Core Value Proposition 
• Frictionless recipe creation – Add ingredients and steps with minimal clicks • Visual recipe documentation – Attach photos to individual cooking stages • Quick access dashboard – See recent activity and jump into new recipes instantly • Clean, focused interface – No clutter, no ads, just your recipes

Application Structure 
The application consists of two primary views: the Home Dashboard and the Recipe Editor. Navigation is minimal and intuitive. 
Home Dashboard 
The landing page that users see upon opening the app. It serves as both a quick-start point for creating new recipes and a hub for recent activity. 
Layout Components 
1. App Header: Logo/app name on the left, user menu on the right 
2. Add Recipe Button: Prominent call-to-action button, visually emphasized 3. Search Bar: Search recipes by name or tag. Shows matching count when filtering. 4. Recent Activity Feed: Grid or list of recently created/edited recipes with thumbnails 
5. Quick Stats: Total recipes count (shows filtered/total when searching) 
User Interactions 
• Clicking "Add Recipe" navigates to an empty Recipe Editor 
• Clicking a recent recipe opens it in View Mode 
• Search: Type in search bar to filter recipes by name or tag in real-time • Duplicate: Click the copy icon on a recipe card to create a duplicate with "(copy)" appended to the name 
• Delete: Click the trash icon on a recipe card. A confirmation dialog appears to prevent accidental deletion. 
Recipe View & Editor 
The recipe page has two modes: View Mode and Edit Mode. Clicking a recipe from the dashboard opens it in View Mode. Users must click the Edit button to make changes. 
View Mode 
A clean, distraction-free presentation of the recipe optimized for reading and cooking. Features include: 
• Hero banner: Full-width image with recipe title and description overlaid • Meta section: Servings count and tags displayed elegantly 
• Ingredients list: Clean two-column layout with ingredient names and amounts • Instructions: Numbered steps with clear typography 
• Edit button: Located in the header to switch to Edit Mode 
• Cook button: Launches full-screen Cooking Mode presentation 
Cooking Mode 
A full-screen presentation mode optimized for cooking. Large, clear text that's easy to read from across the kitchen. The recipe is presented as slides: 
6. Title Slide: Recipe name, description, banner image, and overview (servings, ingredient count, step count) 
7. Ingredients Slide: Complete ingredients list with large, readable text 8. Step Slides: Each cooking step on its own slide with step number and instructions 
Navigation: Previous/Next buttons, clickable progress dots, keyboard arrows (← →), spacebar to advance, Escape to exit. Voice control planned for future release.

Tagging System Details 
The tagging system is a core feature for recipe organization and discovery. It uses free-form input with smart autocomplete suggestions. 
• Input behavior: Users type in a text field. Pressing Enter adds the tag. Backspace on empty field removes the last tag. 
• Autocomplete: As users type, a dropdown appears showing tags that START WITH the typed characters (e.g., typing "veg" shows "Vegetarian" and "Vegan"). • Suggestion list: Vegetarian, Vegan, Gluten-Free, Dairy-Free, Quick, Easy, Dessert, Breakfast, Lunch, Dinner, Snack, Israeli, Italian, Asian, Mexican, Healthy, Comfort Food, Kid-Friendly, Spicy, Soup, Salad, Pasta, Meat, Fish, Chicken, Baking, Holiday, Shabbat, Passover 
• Custom tags: Users can create any tag—not limited to suggestions. Custom tags are saved and appear in future autocomplete. 
• Display: Tags appear as colored pills with × buttons for removal

Technical Requirements for Deployment 
To transform the current mockup into a fully functional, publicly accessible web application, the following technical components are required: 
Frontend 
• React Application: Build production-ready React app using Vite or Create React App 
• Responsive Design: Ensure the UI works well on desktop, tablet, and mobile devices 
• Image Optimization: Compress and resize uploaded images for fast loading 
Backend 
• API Server: Node.js/Express or similar to handle recipe CRUD operations • Database: PostgreSQL, MongoDB, or SQLite for recipe storage 
• Image Storage: Local file system or cloud storage (S3, Cloudinary) for recipe images 
Hosting Options 
Option A: Self-Hosted (Preferred) 
• Dedicated machine (e.g., Raspberry Pi, old laptop, home server) running 24/7 • Dynamic DNS service (e.g., DuckDNS, No-IP) if IP address changes • Reverse proxy (Nginx, Caddy) for HTTPS and domain routing 
• Port forwarding on router (port 80/443) 
Option B: Cloud Hosting (Fallback) 
• Vercel/Netlify: Free tier for frontend, easy deployment from Git 
• Railway/Render: Backend + database hosting with free/low-cost tiers • DigitalOcean/Linode: Full VPS control, ~$5-10/month

Future Enhancements 
The following features are planned for future releases, pending user feedback and priorities: 
1. Voice Control: Hands-free navigation in Cooking Mode using voice commands 2. Collections/Folders: Organize recipes into custom categories 
3. Advanced Filtering: Filter by ingredient, cooking time, or multiple tags simultaneously 
4. Serving Size Scaling: Auto-calculate ingredient amounts for different portions 5. Recipe Import: Paste URL to import recipes from the web 
6. Inline Timers: Clickable timers within cooking stages 
7. Sharing: Share individual recipes via link or export as PDF 
8. User Accounts: Optional login to save personal recipe collections separately 9. Offline Support (PWA): Access recipes without internet connection

Step 1: Set Up React Project 
• Create a new Vite project: npm create vite@latest recipe-app -- --template react 
• Copy the mockup component into src/App.jsx 
• Test locally: npm run dev 
Step 2: Add Backend API 
• Create Express.js server (server.js) 
• Set up SQLite database with tables for recipes, ingredients, and stages • Create REST API endpoints: GET /api/recipes, POST /api/recipes, PUT /api/recipes/:id, DELETE /api/recipes/:id 
• Add image upload endpoint that saves files to /uploads directory

Summary 
Recipe Manager v1.0 focuses on delivering an exceptional recipe creation experience. By keeping the initial scope tight—home dashboard plus recipe editor with ingredients and stages—we can ship quickly, gather feedback, and iterate toward the features users actually need. 
The ultimate goal is to deploy this application to a server and make it accessible to anyone via a custom domain. Whether self-hosted on a local always-on machine or deployed to cloud infrastructure, the app will serve as a practical, everyday tool for managing recipes. 
The measure of success: users should feel that writing a recipe in this app is faster and more pleasant than any alternative.
